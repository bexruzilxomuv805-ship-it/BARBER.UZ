# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Zolotoy Barber" — a full-stack demo web app for a barbershop, in Uzbek (UI text, route paths, and variable
names are in Uzbek — e.g. `xizmatlar` = services, `ustalar` = barbers, `navbat` = appointment/queue). It has a
public client site (services, barbers, online booking, profile) and an admin dashboard (Zentro-style) for
managing the business.

There is no real backend: `json-server` serves `server/db.json` as a REST API and stands in for production
infra. Passwords are stored in plain text in `db.json` — this is intentional for a demo/learning project, not
a bug to fix unprompted.

## Commands

```bash
npm install          # install deps
npm start             # run frontend (Vite, :5173) + backend (json-server, :4000) together — same as npm run dev:all
npm run dev            # frontend only
npm run server          # backend only (json-server --watch server/db.json --port 4000)
npm run build           # production build
npm run preview          # preview production build
npm run lint            # oxlint
npm run gen:images        # regenerate procedural SVG placeholder images (scripts/gen-images.mjs)
```

There is no test suite configured in this repo.

The frontend expects the backend at `http://localhost:4000` (hardcoded in [src/api/client.js](src/api/client.js)
as `API_BASE_URL`). Most login/data-fetch failures during development are because `npm run server` isn't
running — check port 4000 first.

Demo accounts (from README): admin `admin@zolotoy.uz` / `admin123`; client `ali@example.com` / `1234`.

## Architecture

**Redux Toolkit is the single source of truth for all server data.** Every resource-backed slice
(barbers, services, appointments, inventory, payments, customers, reviews) is generated by the factory in
[src/features/common/createCrudSlice.js](src/features/common/createCrudSlice.js): pass `{ name, endpoint }`
and it returns a slice plus `fetchAll`/`createItem`/`updateItem`/`removeItem` thunks that hit json-server via
axios ([src/api/client.js](src/api/client.js)). When adding a new CRUD resource, follow the existing pattern
(see [src/features/barbers/barbersSlice.js](src/features/barbers/barbersSlice.js) for the minimal wiring) rather than
hand-writing thunks. `auth` ([src/features/auth/authSlice.js](src/features/auth/authSlice.js)) and `chat`
([src/features/chat/chatSlice.js](src/features/chat/chatSlice.js)) are bespoke slices with their own logic
(auth persists the logged-in user to `localStorage` under `zolotoy_auth_user`; chat polls json-server every 3s
to simulate live updates since json-server has no WebSocket support). All slices are registered in
[src/app/store.js](src/app/store.js).

**Routing has two independent trees under one `<Routes>`** ([src/App.jsx](src/App.jsx)):
- Public/client routes are nested under `ClientLayout` ([src/layouts/ClientLayout.jsx](src/layouts/ClientLayout.jsx)),
  Uzbek paths (`/xizmatlar`, `/ustalar`, `/navbat-olish`, etc.), pages in `src/pages/client/`.
- Admin routes are nested under `/admin` + `AdminLayout` ([src/layouts/AdminLayout.jsx](src/layouts/AdminLayout.jsx)),
  pages in `src/pages/admin/`.

Route protection is via wrapper components, not layout-level guards:
[ProtectedRoute](src/routes/ProtectedRoute.jsx) requires login (redirects to `/kirish`), and
[AdminRoute](src/routes/AdminRoute.jsx) additionally requires `role === 'admin'` (redirects non-admins to `/`).
Both read auth state through the [useAuth](src/hooks/useAuth.js) hook, which derives `isAdmin` from
`user?.role`.

**Data flow for a typical admin CRUD page**: page component dispatches `fetchX` on mount, reads `items`/
`status`/`error` from the slice via `useSelector`, and dispatches `createX`/`updateX`/`removeX` from
modals/forms built on the shared [Modal](src/components/admin/Modal.jsx) /
[ConfirmDialog](src/components/admin/ConfirmDialog.jsx) / [StatCard](src/components/admin/StatCard.jsx)
components. Charts on the dashboard/reports pages use Recharts.

**Styling**: Tailwind CSS with a custom "barber" theme (`ink` = near-black grays, `gold` = accent) defined in
[tailwind.config.js](tailwind.config.js), plus custom fonts (`Playfair Display` display font, `Inter` sans,
loaded from Google Fonts — needs internet) and custom keyframe animations (`float`, `floatSlow`, `spinSlow`,
`shimmer`, `pulseRing`). Framer Motion is used for scroll-reveal ([src/components/Reveal.jsx](src/components/Reveal.jsx)),
hover, and page-transition animations on top of Tailwind.

**Images**: barber portraits and hero art are procedurally generated SVGs (not photos), produced by
[scripts/gen-images.mjs](scripts/gen-images.mjs) into `src/assets/images/`, re-exported from
[src/assets/images/index.js](src/assets/images/index.js). Regenerate with `npm run gen:images`; replacing with
real photos means swapping the files in place or updating the index.

**PWA**: configured via `vite-plugin-pwa` in [vite.config.js](vite.config.js) (autoUpdate, offline caching,
manifest). `devOptions.enabled` is `false`, so PWA behavior only shows up in `npm run build` + `npm run preview`,
not in `npm run dev`.
